# Azure Virtual Network, Virtual Machines, and Load Balancer - Complete Guide

## Overview

This comprehensive guide walks through creating a complete Azure infrastructure using Terraform that includes:

- **Virtual Network (VNet)** with subnet configuration
- **Network Security Group (NSG)** with security rules
- **Two Linux Virtual Machines** running Ubuntu 22.04 LTS
- **Azure Load Balancer** distributing traffic across VMs
- **Nginx web servers** installed on both VMs

## Infrastructure Components

### 1. Resource Group
- Dynamically named using `random_pet` resource
- Location: East US (configurable)

### 2. Networking
- **Virtual Network**: 10.0.0.0/16 address space
- **Subnet**: 10.0.1.0/24 address range
- **Public IP**: Static allocation, Standard SKU
- **Network Security Group**: Allows HTTP traffic (port 80)

### 3. Compute
- **2 Linux VMs**: Ubuntu 22.04 LTS
- **VM Size**: Standard_B2s (configurable)
- **Storage**: Standard LRS OS disks
- **Authentication**: Password-based (randomly generated if not provided)

### 4. Load Balancing
- **Load Balancer**: Standard SKU, public-facing
- **Backend Pool**: Contains both VMs
- **Health Probe**: Monitors port 80
- **Load Balancing Rule**: Distributes HTTP traffic
- **Outbound Rule**: Manages outbound connectivity

### 5. Application
- **Nginx**: Installed via VM extension
- **Custom Page**: Displays hostname for identification

## Prerequisites

- Azure subscription
- Terraform installed (version supporting azurerm ~>4.0)
- Azure CLI installed and authenticated
- Basic understanding of Azure networking concepts

## Key Features

- **High Availability**: Two VMs behind a load balancer
- **Automatic Scaling Ready**: Infrastructure supports adding more VMs
- **Security**: NSG controls inbound traffic
- **Monitoring**: Health probes ensure VM availability
- **Automation**: Fully automated deployment with Terraform
- **Customization**: Extensive variable support for configuration
