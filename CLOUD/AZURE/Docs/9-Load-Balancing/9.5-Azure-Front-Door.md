# 🚀 End-to-End Tutorial: Azure Blob Storage + Azure Front Door CDN for Website Assets

## 📌 Use Case

You have:

* A frontend website hosted in **Azure App Service**
* Static assets like:

  * Images (`.png`, `.jpg`, `.webp`)
  * Videos (`.mp4`)
  * JS/CSS files

You want:

✅ CDN caching
✅ Faster global delivery
✅ Reduced load on App Service
✅ Best practice Azure architecture

---

# 🏗 Recommended Architecture

```
Users
   ↓
Azure Front Door (CDN + Edge Cache)
   ↓
Azure Blob Storage (Assets Container)

Frontend Website
   ↓
Azure App Service
```

---

# ✅ Why Use Blob + Front Door?

App Service is meant for:

* Hosting frontend/backend apps
* Running server logic

Blob Storage is meant for:

* Cheap static storage
* Large media files
* Unlimited scaling

Front Door provides:

* Global CDN edge caching
* HTTPS support
* Custom domain support
* WAF security (optional)

---

# ✅ Step 1: Create Blob Storage for Assets

## 1. Storage Account

If Storage Account already exists, reference it:

```hcl
data "azurerm_storage_account" "assets_sa" {
  name                = var.storage_account_name
  resource_group_name = var.resource_group_name
}
```

---

## 2. Create Container for Assets

```hcl
resource "azurerm_storage_container" "assets_container" {
  name                  = "assets"
  storage_account_name  = data.azurerm_storage_account.assets_sa.name
  container_access_type = "blob"
}
```

Now your assets will be stored like:

```
https://<storage-account>.blob.core.windows.net/assets/logo.png
```

---

# ✅ Step 2: Create Azure Front Door Profile

Front Door Profile is the main CDN service.

```hcl
resource "azurerm_cdn_frontdoor_profile" "cdn_profile" {
  name                = var.frontdoor_profile_name
  resource_group_name = var.resource_group_name

  sku_name = "Standard_AzureFrontDoor"
}
```

Example:

```hcl
frontdoor_profile_name = "assets-cdn-profile"
```

---

# ✅ Step 3: Create Front Door Endpoint

Endpoint gives you the CDN URL:

```
https://<endpoint>.azurefd.net
```

Terraform:

```hcl
resource "azurerm_cdn_frontdoor_endpoint" "cdn_endpoint" {
  name                     = var.frontdoor_endpoint_name
  cdn_frontdoor_profile_id = azurerm_cdn_frontdoor_profile.cdn_profile.id
}
```

Example:

```hcl
frontdoor_endpoint_name = "assets-cdn-endpoint"
```

---

# ✅ Step 4: Configure Origin Group

Origin Group manages backend health + load balancing.

```hcl
resource "azurerm_cdn_frontdoor_origin_group" "origin_group" {
  name                     = var.origin_group_name
  cdn_frontdoor_profile_id = azurerm_cdn_frontdoor_profile.cdn_profile.id

  load_balancing {
    sample_size                 = 4
    successful_samples_required = 3
  }
}
```

Example:

```hcl
origin_group_name = "blob-assets-origin-group"
```

---

# ✅ Step 5: Add Blob Storage as Origin

Front Door Origin = Blob Storage endpoint.

```hcl
resource "azurerm_cdn_frontdoor_origin" "blob_origin" {
  name                          = var.origin_name
  cdn_frontdoor_origin_group_id = azurerm_cdn_frontdoor_origin_group.origin_group.id

  enabled                        = true
  host_name                      = data.azurerm_storage_account.assets_sa.primary_blob_host
  origin_host_header             = data.azurerm_storage_account.assets_sa.primary_blob_host
  certificate_name_check_enabled = true

  http_port  = 80
  https_port = 443

  priority = 1
  weight   = 100
}
```

Example:

```hcl
origin_name = "blob-storage-origin"
```

---

# ✅ Step 6: Create Front Door Route (Container Mapping)

Azure Front Door does not directly know the container name.

So you must route requests like:

```
/assets/*
```

Terraform:

```hcl
resource "azurerm_cdn_frontdoor_route" "assets_route" {
  name                          = var.route_name
  cdn_frontdoor_endpoint_id     = azurerm_cdn_frontdoor_endpoint.cdn_endpoint.id
  cdn_frontdoor_origin_group_id = azurerm_cdn_frontdoor_origin_group.origin_group.id

  cdn_frontdoor_origin_ids = [
    azurerm_cdn_frontdoor_origin.blob_origin.id
  ]

  enabled = true

  patterns_to_match = [
    "/${azurerm_storage_container.assets_container.name}/*"
  ]

  supported_protocols = ["Http", "Https"]
  forwarding_protocol = "HttpsOnly"

  link_to_default_domain = true

  cache {
    compression_enabled           = false
    query_string_caching_behavior = "IgnoreQueryString"
  }
}
```

Example:

```hcl
route_name = "assets-cdn-route"
```

---

# ✅ Step 7: Deploy Terraform

Run:

```bash
terraform init
terraform plan
terraform apply
```

---

# ✅ Step 8: Upload Assets to Blob

Example upload:

```bash
az storage blob upload \
  --account-name <storage-account-name> \
  --container-name assets \
  --name images/logo.png \
  --file ./logo.png
```

---

# ✅ Step 9: Access Assets Through CDN

### Blob URL:

```
https://<storage-account>.blob.core.windows.net/assets/images/logo.png
```

### Front Door CDN URL:

```
https://assets-cdn-endpoint.azurefd.net/assets/images/logo.png
```

Now assets are served globally from edge cache 🎉

---

# ✅ Step 10: Use CDN in App Service Frontend

In your frontend code:

```html
<img src="https://assets-cdn-endpoint.azurefd.net/assets/images/logo.png" />
```

For videos:

```html
<video controls>
  <source src="https://assets-cdn-endpoint.azurefd.net/assets/videos/demo.mp4" />
</video>
```

# ✅ CDN Setup for Other Azure Services

Azure has **one main modern CDN platform** now:

## ⭐ Azure Front Door (Standard/Premium)

Front Door can sit in front of:

* Blob Storage
* App Service
* Static Web Apps
* AKS Ingress
* API Management
* Any public HTTP backend

---

# ✅ Best CDN Options by Service

---

## 1️⃣ App Service + Front Door CDN (Full Website Acceleration)

If you want CDN for your full frontend site:

```
Users → Front Door → App Service
```

### Use Case:

* Global website performance
* Custom domain + SSL
* WAF protection

Terraform origin becomes App Service host:

```hcl
resource "azurerm_cdn_frontdoor_origin" "app_origin" {
  name                          = "appservice-origin"
  cdn_frontdoor_origin_group_id = azurerm_cdn_frontdoor_origin_group.origin_group.id

  host_name          = azurerm_linux_web_app.frontend.default_hostname
  origin_host_header = azurerm_linux_web_app.frontend.default_hostname

  https_port = 443
}
```

Then route:

```hcl
patterns_to_match = ["/*"]
```

---

## 2️⃣ Azure Static Web Apps (Built-in CDN)

Static Web Apps already includes global distribution.

So no extra CDN needed if:

✅ Fully static React/Vue frontend

URL:

```
https://yourapp.azurestaticapps.net
```

Best for:

* Static sites
* Jamstack apps

---

## 3️⃣ AKS + Front Door CDN (Kubernetes Workloads)

If your frontend/backend runs in AKS:

```
Users → Front Door → AKS Ingress Controller
```

Origin is Ingress public IP / DNS:

```hcl
host_name = "myaks-ingress.mydomain.com"
```

Best for:

* Microservices
* Global traffic routing

---

## 4️⃣ API Management + Front Door

For APIs:

```
Users → Front Door → API Management → Backend
```

Benefits:

* API caching
* WAF protection
* Global routing

Origin:

```hcl
host_name = azurerm_api_management.apim.gateway_url
```

---

## 5️⃣ Azure Storage (Blob, Static Website, Files)

Blob is the most common CDN backend.

Best for:

* Images
* Videos
* Downloads

---

## 6️⃣ Azure Container Apps + Front Door

Container Apps provide a public endpoint.

```
Users → Front Door → Container App
```

Origin host:

```hcl
host_name = azurerm_container_app.app.latest_revision_fqdn
```

---

## 7️⃣ Azure VM / NGINX + Front Door

If you have a VM running a website:

```
Users → Front Door → VM Public IP/DNS
```

Origin:

```hcl
host_name = "vm-web.mydomain.com"
```

---

# 🔥 One Front Door, Multiple Origins (Best Practice)

You can configure:

* `/assets/*` → Blob Storage
* `/api/*` → API Management
* `/*` → App Service frontend

Example routing:

| Path Pattern | Backend        |
| ------------ | -------------- |
| `/assets/*`  | Blob Storage   |
| `/api/*`     | API Management |
| `/*`         | App Service    |

That’s the most scalable production setup.
