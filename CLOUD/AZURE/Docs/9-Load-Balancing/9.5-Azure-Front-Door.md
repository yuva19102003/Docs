# 1️⃣ What is Azure Front Door?

**Azure Front Door** is a **global, Layer-7 (HTTP/HTTPS) edge service** from **Microsoft Azure**.

It provides:

* 🌍 Global load balancing
* ⚡ Anycast routing (closest edge)
* 🔐 Built-in WAF
* 🚀 CDN-like performance
* 🧠 Intelligent failover

👉 Think of it as **Cloudflare + CDN + L7 Load Balancer** combined.

---

## 2️⃣ When Should You Use Azure Front Door?

Use **Azure Front Door** when:

✅ Users are globally distributed
✅ You need low latency worldwide
✅ You want edge-level security (WAF)
✅ You want automatic regional failover
✅ You want HTTPS + certs without managing infra

❌ Not for TCP/UDP
❌ Not for internal/private-only apps

---

## 3️⃣ Azure Front Door Mental Model (Very Important)

```
User (anywhere in world)
        ↓
Nearest Azure Edge Location (Anycast)
        ↓
Azure Front Door
   ├─ WAF (OWASP rules)
   ├─ Routing rules
   ├─ Health probes
        ↓
Origin (Backend)
   ├─ App Gateway
   ├─ Load Balancer
   ├─ App Service
   ├─ AKS
```

## 4️⃣ Azure Front Door vs Application Gateway vs Load Balancer

| Feature         | Front Door | App Gateway | Load Balancer |
| --------------- | ---------- | ----------- | ------------- |
| Scope           | 🌍 Global  | Regional    | Regional      |
| OSI Layer       | L7         | L7          | L4            |
| Anycast         | ✅          | ❌           | ❌             |
| WAF             | ✅          | ✅           | ❌             |
| CDN             | ✅          | ❌           | ❌             |
| Private backend | ❌          | ✅           | ✅             |

👉 **Rule of Thumb**

* Global users → **Front Door**
* Regional web apps → **App Gateway**
* Infra traffic → **Load Balancer**

## 5️⃣ Core Components of Azure Front Door

### 🧩 Profile

Top-level Front Door configuration.

### 🧩 Endpoint

Public hostname:

```
xxxxx.azurefd.net
```

### 🧩 Origin

Backend service:

* App Gateway
* App Service
* Load Balancer
* AKS ingress

### 🧩 Origin Group

Group of origins with:

* Priority
* Weight
* Health probe

### 🧩 Route

Defines:

* URL patterns
* Which origin group to use
* HTTPS settings

### 🧩 WAF Policy

Security rules (OWASP + custom)

## 6️⃣ End-to-End: Create Azure Front Door (Portal)

### 🔧 Step 1: Create Front Door Profile

Azure Portal → **Front Door and CDN** → **Create**

| Setting      | Value                       |
| ------------ | --------------------------- |
| Tier         | **Standard** or **Premium** |
| Profile name | `fd-global-app`             |

---

### 🔧 Step 2: Create Endpoint

| Setting       | Value          |
| ------------- | -------------- |
| Endpoint name | `global-web`   |
| Hostname      | auto-generated |

---

### 🔧 Step 3: Add Origin Group

| Setting      | Value             |
| ------------ | ----------------- |
| Name         | `primary-origins` |
| Health probe | Enabled           |
| Probe path   | `/health`         |
| Interval     | 30s               |

---

### 🔧 Step 4: Add Origins

Example:

* Origin 1: App Gateway (East US)
* Origin 2: App Gateway (West Europe)

| Setting  | Value                     |
| -------- | ------------------------- |
| Priority | 1 (primary), 2 (failover) |
| Weight   | 100                       |

---

### 🔧 Step 5: Create Route

| Setting             | Value               |
| ------------------- | ------------------- |
| Domains             | Front Door endpoint |
| Patterns            | `/*`                |
| Origin group        | primary-origins     |
| HTTPS               | Enabled             |
| Forwarding protocol | HTTPS only          |

## 7️⃣ Health Probes in Azure Front Door

Front Door continuously checks backend health.

**Best practice**

```http
GET /health
200 OK
```

If origin fails:

* Automatically removed
* Traffic routed to next healthy origin

👉 Zero-downtime regional failover

---

## 8️⃣ Enable WAF in Azure Front Door

### 🔐 Step 6: Create WAF Policy

Front Door → **WAF policies** → Create

| Setting  | Value             |
| -------- | ----------------- |
| Mode     | Detection (start) |
| Rule set | OWASP 3.2         |
| Scope    | Global            |

Attach WAF policy to:

* Front Door endpoint
* Specific routes

## 9️⃣ Test WAF Rules (Hands-On)

### 🧪 SQL Injection

```bash
curl "https://<fd-endpoint>/?id=1 OR 1=1"
```

### 🧪 XSS

```bash
curl "https://<fd-endpoint>/?q=<script>alert(1)</script>"
```

**Detection mode**

* Request allowed
* Logged in diagnostics

**Prevention mode**

* ❌ 403 Forbidden

## 11️⃣ Azure Front Door Security Best Practices

✅ Always use HTTPS
✅ WAF in Prevention mode (after testing)
✅ Restrict backend to Front Door IPs
✅ Health probes with fast failover
✅ Use Premium for private link support

## 15️⃣ Interview-Ready Explanation (30 Seconds)

> Azure Front Door is a global Layer-7 load balancing and security service that uses Anycast routing to direct users to the nearest healthy backend. It provides built-in WAF, CDN acceleration, SSL termination, and automatic regional failover, making it ideal for globally distributed web applications.
