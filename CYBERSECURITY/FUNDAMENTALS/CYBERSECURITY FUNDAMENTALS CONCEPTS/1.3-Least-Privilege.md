## **Least Privilege (PoLP - Principle of Least Privilege)**

The **Principle of Least Privilege (PoLP)** ensures users, systems, and applications get only the **minimum access** required to perform their tasks, reducing security risks.

---

### **🔹 Key Principles**

✅ **Minimal Access** – Users should only have necessary permissions.  
✅ **Time-Limited Access** – Temporary access should expire after use.  
✅ **Separation of Duties** – Prevents a single user from having full control.  
✅ **Regular Audits** – Periodically review and remove unnecessary permissions.  
✅ **Restricted Admin Access** – Root/Admin privileges should be minimal.

---

### **🔹 Real-World Examples**

🔹 **AWS IAM:** Use **IAM roles** instead of giving full access.  
🔹 **Linux Servers:** Developers should have **limited sudo access** via the sudoers file.  
🔹 **Database Security:** Grant **read-only access** to most users, write access to a few.

---

### **🔹 Benefits**

✅ **Reduces Attack Surface** – Limits exposure to security threats.  
✅ **Prevents Accidental Damage** – Users can’t modify critical data.  
✅ **Minimizes Lateral Movement** – Attackers can’t spread easily.  
✅ **Ensures Compliance** – Meets **GDPR, HIPAA, ISO 27001** standards.

---

### **🔹 Implementation in Cloud & DevOps**

🔹 **Use IAM roles & RBAC** for access control.  
🔹 **Restrict Kubernetes cluster access** with RBAC policies.  
🔹 **Limit SSH access** using Bastion Hosts.  
🔹 **Manage secrets** using tools like HashiCorp Vault.
